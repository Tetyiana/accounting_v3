## Що зроблено в сесії 2026-08-20 (велика)

### Знайдено причину «зниклих даних»
Тетяна вела ФОПа з 26.07, у базі не було нічого. Причини виявилось дві:
1. `dbInsert` був fire-and-forget з `.then(({error}))` **без `.catch`** — при
   недоступній базі fetch кидає виняток, `.then` не спрацьовує, помилка гине.
2. Схема бази розійшлася з кодом — insert повертав 400 (див. нижче).
Дані по тому ФОПу **не відновлені — їх ніколи не було в базі**.

### Полагоджено
- `src/lib/db.js`: `.catch` на insert + **черга незбережених** у localStorage
  (`db_pending_v1`), `flushPending()`, `pendingCount()`. Записи з непоправною
  помилкою схеми (код `PGRST*`) відкидаються з черги, щоб не залипали.
- `src/App.jsx`: `flushPending()` при вході і на `window.online`.
- `MainLayout.jsx`: компонент `PendingBadge` — червона кнопка «⚠ Не збережено: N»
  у шапці, клік = ручна спроба дозапису. Оновлення раз на 5 с.
- Кошик: `deleteClient/deleteProduct/deleteContract` тепер пишуть у `trash`
  (раніше видаляли назавжди); `restoreFromTrash` навчений `client/product/contract`;
  `TrashView` показує людські назви типів і опис для всіх сутностей.
- `dbSelect` сортує `trash` по `deleted_at` (була помилка — сортував по `created_at`).
- Прибрано мертве поле `vatCertificate` з форми контрагента (свідоцтва ПДВ
  не існує ~10 років, ідентифікатор — ІПН; Тетяна вказала на це).
- keep-alive: інтервал 2 дні, `--max-time 30`, зрозуміле повідомлення при паузі.
  **Важливо: пінг не будить паузований проєкт, тільки не дає заснути.**
- Переїзд на Cloudflare Pages; `vite.config.js`: `base: process.env.CF_PAGES ? '/' : '/accounting_v3/'`.
- Supabase Site URL оновлено на pages.dev.

5. Накладна і акт — РІЗНІ друковані форми (Постачальник/Одержувач vs Виконавець/Замовник).
6. Ставки 2026: МЗП 8647, ЄСВ 1902.34, ЄП гр1 332.80 / гр2 1729.40,
   ВЗ фікс 864.70, гр3 5%/3%+ВЗ 1%. **Перевіряти на актуальність.**

## Граблі
- **Схема БД розходиться з кодом мовчки.** Перед додаванням будь-якого поля в
  форму — звірити з реальною схемою. Швидка звірка:
  ```sql
  select table_name, string_agg(column_name, ', ' order by ordinal_position)
  from information_schema.columns where table_schema='public'
  group by table_name order by table_name;
  ```
- camelCase→snake_case: абревіатури ламаються (`useRRO`→`use_r_r_o`). Мапа SPECIAL у db.js.
- sed/regex-заміни двічі давали приховані краші — тільки python-патчі з assert + grep після.
- iOS-клавіатура вставляє «Є» в кінець SQL.
- Supabase free-tier: пауза після 7 днів неактивності. Заснув проєкт — будити руками.
- Тетяна іноді пише з англійською розкладкою («pfgeibkf» = «запушила») — не перепитувати зайвий раз.
